# Replace Caddy with nginx inside the image

**Status:** implemented
**Date:** 2026-10-12

## Goal

The upstream project serves uploads with a separate `caddy:2-alpine` container
that mounts `./uploads` read-only and a `Caddyfile`. We ship a **single** image
(backend + frontend + reverse proxy), so the proxy must live in the same
container and be configured in the repository.

## Decision

Use **nginx** (Alpine package) instead of Caddy:

-   already available in the `node:20-alpine` base via `apk add nginx`;
-   battle-tested for huge static files: native `sendfile`, zero-copy, `Range`
    support (resumable/partial downloads of multi-GB uploads), and
    `client_max_body_size 0` + `proxy_request_buffering off` for streamed uploads;
-   no certificate automation needed in-container: TLS stays outside the image
    (host reverse proxy / Cloudflare / DNS-01 terminator), exactly like the old
    Caddy setup that only served plain HTTP on `:80`.

## Routing (replaces the Caddyfile)

`container/nginx.conf`:

| Path                   | Behaviour                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------- |
| `/api/*`               | `proxy_pass http://127.0.0.1:8000` (backend, path preserved)                                      |
| `/docs`, `/docs/*`     | `proxy_pass http://127.0.0.1:8000` (Scalar API reference)                                         |
| everything that exists | served from `root /app/uploads` (`try_files`) → `/app/uploads/<file>`, `/thumbs/...`, `/live/...` |
| anything else          | `proxy_pass http://127.0.0.1:8001` (Next.js frontend)                                             |

Notes:

-   Longer prefix locations win in nginx, so `/api/` and `/docs` are matched
    before the `/` fallback.
-   `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Real-IP`, `Host` are forwarded so
    Fastify's `trustProxy: true` keeps logging real client IPs and the IP-ban
    middleware keeps working.
-   `client_max_body_size 0;`, `proxy_request_buffering off;`,
    `proxy_read_timeout 600s;` and `proxy_send_timeout 600s;` are required for the
    > 2 GB upload fix: nginx must not buffer or truncate large request bodies.
-   Logs go to stdout/stderr so `docker logs` shows both access and error logs.
-   Optional `uploads.d/client*` includes keep the config extensible without
    rebuilding the image.

## Files

-   `container/nginx.conf` – the server config (replaces `Caddyfile`).
-   `docs/migrating-v3-to-v4.md` – updated to point at nginx in `docker/` instead
    of Caddy.
-   `docker/docker-compose.yml` – the old `caddy` service is gone; the combined
    image listens on a single port.

## Verification

-   `nginx -t` passes during `docker build` and inside the running container
    (`docker exec … nginx -t` → _syntax is ok / test is successful_).
-   `docker run` smoke test on the built image, all through port 80:
    `/` → `200` (Next, `Server: nginx`), `/api/health` → `200 {"status":"yes"}`,
    `/api/version` → `{"version":"test"}` (Fastify through nginx), `/api/settings`
    → `200`, `/docs` → `200` (Scalar), `/thumbs/` → `308` (nginx serving
    `/app/uploads`). The container's own healthcheck reports `healthy`.
-   Large-body path: a 2.5 GiB chunked upload (34 requests of ~81 MB) completes
    with no `413`/truncation, and `Range: bytes=2684354000-2684354559` on the
    stored file answers `206` with the last 560 bytes (see
    `2026-10-12-upload-over-2gb.md` for the byte-level hashes).

## Limitations

-   No TLS termination in-container by design; terminate TLS in front of it.
-   If an operator wants to serve uploads from a CDN/`serveUploadsFrom` that still
    works, since that URL is generated by the backend, not by nginx.
